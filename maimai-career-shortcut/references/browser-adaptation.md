# 浏览器选择、登录与后台执行

每次运行先读本节，使用当前宿主实际提供且用户已配置的浏览器能力。浏览器选择依据工具和会话能力，不按产品名称写死。

## 选择执行路径

尊重用户本次明确指定的浏览器或会话；未指定时按以下顺序选择：

1. **优先内置浏览器**：宿主提供可操作的内置浏览器，能够打开页面、完成交互、读取正常呈现的页面内容并复用登录会话时，直接使用。例如 Codex、豆包工作等宿主在当前会话提供这些能力时采用此路径。不要求另外安装系统浏览器或连接器。
2. **使用宿主已配置的浏览器工具**：内置浏览器不可用，或无法完成本任务的交互、读取、登录会话复用时，使用用户在宿主中已启用的浏览器自动化技能、浏览器 MCP、扩展或 CDP 工具。WorkBuddy 等宿主可采用此路径；具体浏览器、用户配置文件、连接实例及打开方式均沿用宿主设置，不固定为 Chrome 或 Edge。宿主配置为系统默认浏览器时，使用该用户的实际默认浏览器。
3. **只有打开链接能力**：能用宿主工具打开网址，但没有可用的页面控制与登录态读取能力时，可以打开脉脉官方页面供用户登录；将其记为“仅能打开，尚不能查询”。说明还缺哪项浏览器工具或连接，让用户在宿主中配置；不能把打开成功或用户说已登录当作已能自动抓取。
4. **没有浏览器入口**：说明当前缺少的能力及配置位置（仅依据宿主实际提供的信息），保留已核验进度，待用户启用浏览器工具后继续。不编造已安装的连接器、工具名、设置入口或调试端口。

先检查当前工具清单及已有连接；已有设置足够时直接执行，不重复要求用户选择浏览器或重新安装。多个连接无法判断该用哪个时，只询问缺失的选择。`browser-automation-cdp` 等名称可作为用户已配置工具的例子，不是安装本 Skill 的固定依赖；是否可用以当前宿主实际暴露的工具为准。需要新增连接或安装组件时，按宿主的配置和授权流程处理，不因截图中提到某个组件就自动安装。

只使用宿主允许的工具通道及其文档。不自行猜测调试地址、启动远程调试或读取浏览器配置文件、密码库、Cookie 来绕开缺失的会话能力。安装 Skill 不会自动安装浏览器驱动、MCP 或扩展。

## 登录会话

- 在**选定且可控制的浏览器会话**中核验脉脉登录。外部浏览器通过宿主工具连接后，与内置浏览器遵循相同的登录和数据核验规则。
- 当前会话已登录时直接复用；未登录或过期时，在该会话打开并保留脉脉官方登录页，交给用户完成登录或验证码，再读取页面确认成功。无需让已登录用户反复扫码。
- 后续搜索、翻页、帖子及岗位详情读取都沿用这个会话。不默认不同浏览器、不同用户配置、手机 App 或其他 Agent 的登录互通；不能以匿名网页抓取替代需要登录的查询。
- 切换执行路径时先保存进度，再核验新会话；旧会话中的已核验结果保留，受限页面在新会话中继续。不能通过手工导出或复制登录凭据迁移会话。

## 后台与可见性

优先后台查询，避免抢焦点和为每条结果打开一个前台页面。登录、验证码和用户主动要求查看时可以展示页面。

- 工具支持隐藏研究页面时，使用隐藏模式。
- 宿主提供后台标签页、窗口或其他执行模式时，沿用用户对此宿主的设置，复用少量研究页。仅后台标签、最小化或不抢焦点不等于完全隐藏，不宣称用户看不到这些页面。
- 仅能可见操作时，如用户的宿主设置或本次指令允许可见执行，按该配置继续并简短说明实际方式；不因缺少完全隐藏能力就否定已可用的浏览器工具。
- 用户明确要求完全隐藏，而当前所有已配置路径均无法满足时，说明该项限制、保存进度并暂停依赖它的查询，等待用户调整设置或同意可见方式；不把超时或沉默当作同意。

## 能力与完成状态

开始查询前至少确认：能打开选定浏览器、能交互与读取页面、能复用并验证脉脉登录。可见性按上面的规则单独处理；“能打开”“能控制读取”“已登录”“可完全隐藏”分别记录，不相互替代。

审核记录只保存执行模式（内置或宿主配置）、能力状态、登录核验结果、实际可见性和必要的受限原因；不保存连接密钥、调试端点、会话标识或登录凭据。未配置、未登录、验证码及页面受限均不等于没有岗位或内推。

不同宿主的导入、浏览器控制、会话复用及文件输出能力需要实际验证。说明“已更新适配规则”即可，未在相应宿主跑通前不声称已经完成 WorkBuddy、豆包工作等平台的实机适配。
