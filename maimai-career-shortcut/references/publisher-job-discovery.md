# 岗位发现与核验（登录后后台执行）

岗位是内推与公司找人清单的补充。默认链路为“登录后读取内推原帖 → 确认公司 → 关联岗位”。先按 [浏览器适配规则](browser-adaptation.md) 选择宿主可操作的内置浏览器，或用户在宿主中配置的浏览器工具，并确认其中的脉脉登录。后续读取复用选定的可控会话，优先后台执行；可见性遵循用户的宿主设置及本次要求，不将没有内置浏览器视为无法执行。无需 NBI、私有库或未开放 API；不查找具体员工，不打开个人主页或通过主页职位列表抓岗位。文件名保留以兼容已有引用。

## 发现与读取

1. 优先读取内推原帖中真实可见的岗位链接。没有链接时，在脉脉官网公开岗位列表、列表可见的搜索/筛选入口或公开网页搜索中发现同公司岗位；搜索摘要只作发现，不能代替详情。
2. 已观察到的官网入口包括 `https://maimai.cn/n/platform/homepage/jobs`，实际岗位列表可能为 `/n/platform/job-list`，详情可能为 `/n/job/geo/...`；旧版真实详情可能为 `/jobs/job_detail?ejid=...`。除已核验入口外，仅跟随可见链接，不猜测未知路径、岗位 ID 或隐藏接口。
3. 在选定的同一登录会话内，先按列表卡片名称、公司、城市、薪资初筛，再读取真实详情的标题、薪资、招聘公司、地点、学历、年限与 JD；优先后台读取，复用少量研究页，实际可见性按浏览器适配规则处理。多城市明示含目标城市可纳入；发布者所在地、公司注册地址不能替代岗位所在地。
4. 招聘公司以详情为准；岗位和帖子可以仅为同公司关联，不补造“帖子 → 员工 → 岗位”的链条。仅有岗位页面明确的直招/猎头信息时记录该分类，不为核验身份打开个人主页。
5. 按真实 ejid 或公开详情路径中的岗位标识去重；同一岗位不同入口合并来源。不同链接但名称或职责高度相近时标记可能重复，不当作独立 HC。岗位数只统计本次详情已读取并通过筛选的岗位，不用列表总数、招聘帖数或搜索估计替代。
6. 原文仅整理换行，不补造缺失条件。明示关闭、失效或下架的不进入推荐。页面可读但状态不明时，只说明本次详情可访问，是否仍招由站内确认。
7. 登录失效时暂停会话读取、保留进度，在选定浏览器会话展示并保留官方登录页让用户恢复；确认会话恢复后继续核验。验证码由用户处理，其他访问限制记录受限；不以摘要补齐 JD，不用独立匿名请求冒充登录结果，依然不打开个人主页。
8. 按实际列表翻页/滚动，连续两次无新增、候选耗尽或来源受限时结束该来源。关联岗位默认最多20条、单份最多50条；用户指定数量则以其要求为目标，实际不足如实交付，不放宽硬条件凑数。

## 核验字段

审核记录保留真实岗位标识、`detail_url`、`observed_at`、`discovery_method`（如 `referral_post_link`、`official_job_list`、`web_search_discovery`）、`source_referral_url`、实际列表来源、JD 原文、筛选理由、访问状态与待确认条件。新记录不采集发布者姓名、个人主页、个人职位列表或履历；帖子作者显示名按原帖规则处理。新发现的同公司岗位保留独立来源，不伪称原帖作者承诺内推。

检索来源、登录会话核验状态和读取成功状态另存有限审核记录，不保存会话标识或凭据。技能只从本次可读且符合目标的详情 JD 统计；受限详情不进入样本分母。岗位不足不阻塞内推帖与公司找人入口交付。

“查看岗位详情”指向已核验的 HTTPS 官网真实详情，保留原有参数；点击只表示打开岗位，不自动投递。清单只展示摘要，不折叠展开完整 JD；原帖、公司找人入口与岗位链接分别回到真实承接页，站内登录与权限由脉脉处理，不统一换成首页、应用宝或下载页。
